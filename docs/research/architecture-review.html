Problem. GENERATORS looks like the seam, but each model kind is still known in eight hand-maintained places, so the core's interface for "check the Models" is as wide as its implementation.

Solution. Each model kind declares its file, schema, whether the element rule applies, and its one step in a check (diff an Element list, or judge something against authored rules). answer, read_sources, MODEL_FILES and the seam test read that list.

  • Real seam: five adapters, not one
Keeps docs/diagrams/model-seam.md (D9, D10) intact: owners still write generate_x(files) -> dict and their schema. Only the core side deepens.

Problem. model_drift.py repeats the core's read, scope, decode and generate steps with weaker rules (no 1 MB limit, bad files silently dropped, a broken scope.json falls back to the default), and it calls Comparison methods that the Reader interface does not have.

Solution. Add reading at a given commit to the Reader interface, and let one core function return what the page shows. The core then decides once whether a page is strict or lenient.

  • Locality: one read path, one set of error rules
  • The page runs on the CLI's LocalReader too
  • Untested route gets a test surface
  • The HTTP route stops importing the Frontend
Glossary clash: the page's "drift" chip means "the regenerated model changed since the parent commit". GLOSSARY.md defines Drift as code vs Models. That chip needs its own name.

The core passes in rules read at the base. The module's interface is where "which commit's rules count" is decided.

Problem. Understanding ownership means reading both files, and the top fix in the perspectives docs (judge against rules at the base commit) has no single place to land.

Solution. Bring log parsing, judging and the shape check together behind propose and judge. The base-commit rule then becomes one parameter of judge.

  • Change types defined once, not twice
model-seam.md gives the checker to the core and propose_ownership to the ownership owner. This merges code two people own, so the owners have to agree on the split first. That is an agreement between people, not a technical blocker.

Problem. The seam is real, with two adapters, but both re-parse git's output formats. Every drift test builds a real git repo, because nothing else can produce Sources.

Solution. Put git's output formats in one module that both adapters use. Add an in-memory adapter so tests can check every no-verdict code and the ownership rules without git.

  • Three adapters justify the seam
  • Locality: one git-format parser
  • Fast tests through read_sources
  • Keep one real-git agreement test

Problem. The generator interface takes text, so the trees are thrown away. Both owners walk definitions with the same "last definition wins" rule, and behavioral borrows structural's id scheme.

Top recommendation

A. One model-kind seam for the drift check

Both top proposals in the perspectives docs change model kinds: an authored rules.json is a new kind, and judging ownership at the base commit changes how one kind is read. Today each of those changes touches eight places. Do A first and both land in one place each. C and E then fit in as how individual kinds are written.
